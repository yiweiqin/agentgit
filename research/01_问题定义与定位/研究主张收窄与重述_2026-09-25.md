# 研究主张收窄与重述（2026-09-25）

> **触发原因**：2026-09-25 的相关工作检索（见 [相关工作证据矩阵.md](../02_相关工作与文献/相关工作证据矩阵.md) 第二版与 [相关工作原文证据摘录.md](../02_相关工作与文献/相关工作原文证据摘录.md) 第二版）发现，ISCC 的三根支柱中有两根已被 2026 年的独立工作完整占据，并出现三条**直接质疑本项目机制有效性**的实验证据。

| 14 | 非退化并行度（H5 / \(\tau_{parallel}\)） | **强化为主贡献** | Claim Plane 确认性研究自报 96.7% 序列化且未达目标；agent-semaphore 报告冲突是被 catch-up 消除而非被 claim 消除 | 升为**主结果的前置条件**，并作为与全部写入前准入工作的核心区分点 |

## 3. 重构后的贡献表述

### 3.1 中文

> 本文研究多会话 agent 并行开发下的**调和吞吐失配**。我们指出：Git 工作流的隐含设计前提是变更到达速率 \(\lambda\) 与调和能力 \(R\) 同量级；当一名或多名开发者各自驱动多个有界上下文的 agent 并行修改同一代码库时，\(\lambda\) 跃升若干数量级而 \(R\) 不变，未被调和的变更开始累积，仓库进入局部自洽但全局不可解释的形态。
>
> 本文做出三项贡献。
> **第一，测量学贡献。** 我们论证**失效态在原理上不可由仓库历史观测**——未调和的变更按定义不在 commit 图内，主流版本控制数据在构造上就看不到该现象；该结论由两处独立证据支持（本仓 Flask 提交图的实测负结果，以及 git 原生协调日志的失效模式分析）。据此我们给出 \(\lambda\)、\(R\) 与积压 \(B(t)\) 的可执行估算规程、各自已知弱点，以及一个**健康基线标定**（在收敛成熟项目上 \(\lambda\approx R\)、积压下界接近零）。
> **第二，理论贡献。** 我们把上述失效归因为速率–调和失配而非 Git 的功能缺陷，并把**行为兼容但语义归属被稀释**（同一代码实体被多会话反复触碰后，其保留形态无法回溯到任何单一有效任务）确立为一类**冲突类检测在定义上无法覆盖**的独立失效；同时报告该失效与「意图层语义偏离」的层级差异。
> **第三，实证贡献。** 我们在 Git 兼容前提下评估一个**代行人类调和职责的外部治理 agent**（跨会话、以持久结构化账本为状态、在写入前介入），并采用**非退化并行度**作为主结果的前置条件：收益必须在控制有效并行度 \(P\) 后仍然存在，且必须同时报告阻塞时长、lock starvation 与单位有效功能吞吐。

### 3.2 English

> We study the **throughput mismatch between change arrival and reconciliation** in multi-session agent development. Git's workflow implicitly assumes that the change arrival rate \(\lambda\) is of the same order as the reconciliation capacity \(R\). When one or more developers each drive several bounded-context agents against a shared repository, \(\lambda\) rises by orders of magnitude while \(R\) does not, unreconciled changes accumulate, and the repository becomes locally coherent but globally inexplicable.
>
> We make three contributions. **First (measurement),** we argue that the failure state is **in principle unobservable from repository history**—unreconciled changes are by definition absent from the commit graph—and support this with two independent lines of evidence: a negative result from replaying a mature project's commit graph, and failure modes recoverable only from a git-native coordination log. We then give executable estimation procedures for \(\lambda\), \(R\), and backlog \(B(t)\), state their known weaknesses, and provide a **healthy-baseline calibration** in which \(\lambda\approx R\) and the backlog lower bound is near zero.
> **Second (theory),** we attribute the failure to a rate–capacity mismatch rather than to a functional defect of Git, and establish **behavior-compatible but attribution-diluted edits**—where repeated concurrent touches leave a code entity whose retained form cannot be traced to any single effective task—as an independent failure class that **conflict detection cannot cover by definition**, distinguishing it from intent-level semantic drift.
> **Third (empirical),** we evaluate, on top of Git, an **external governance agent that takes over the reconciliation duties Git's workflow assigns to humans** (cross-session, state held in a persistent structured ledger, intervening before the write), and adopt **non-degenerate parallelism** as a precondition for the primary result: any benefit must survive controlling for effective parallelism \(P\), and must be reported alongside blocking time, lock starvation, and validated feature throughput.

## 4. 新的一页式研究摘要（替换主文档 §30）

**问题。** Git 工作流的隐含前提是 \(\lambda\approx R\)。多会话 agent 开发打破该前提，而非暴露 Git 的功能缺陷：变更由有界上下文的 agent 高频产生，而**归属、验证与并入可解释状态**的速率仍受人类审查与提交粒度约束。其后果中有一类不依赖任何冲突发生——同一代码实体被反复触碰后语义归属被稀释。

**空白。** 写入前准入（Claim Plane、ATM）、写入时一致性（STORM）、五层协调协议（MPAC）、意图一等对象（AVCS、Drift、Claw VCS、Smelt）、语义冲突检测与消解（ConflictLens、Rover、SafeMerge）、多 agent 失效分类（MAST）与语义漂移监测（SCF）均已成熟。**未被占据的是**：把 \(\lambda/R\) 失配建模为可观测积压、据此论证失效态不可由仓库历史观测，以及要求治理收益在控制有效并行度后仍然成立。

**方法。** 在 Git 兼容边界内实现一个外部治理 agent（写入前介入、跨会话、状态在持久结构化账本），并以受控任务与历史回放两条轨道评估；把「非退化并行度」写入主结果的前置条件。

**评价。** 先立前置条件再报效应：\(P\) 与主结果同报；显式报告阻塞时长、lock starvation 与单位有效功能吞吐；消融「只记录不治理（instrument）」与「治理（governor）」以分离观测者效应。

**可证伪结论。** 若 (a) 失配模型无临界比，或 (b) 积压与不可解释度无关，或 (c) 控制 \(\lambda/R\) 后 agent 变更与人类变更的不可解释度无差异（即只是「量」的问题），或 (d) 收益完全来自阻塞，则相应层级的主张必须撤回或降级。

## 5. 三条对抗性证据与应答草稿（必须进入正文）

### 5.1 「指定协调者无效」（When Agents Coordinate，1902 runs）

**必须承认**：在**会话内消息协调**的设定下，指定一个 coordinator 无可靠收益。

**应答**：被否证的是「会话内消息协调者」，本项目主张的是**跨会话、无消息通道、仅共享结构化账本的外部协调者**。可操作的区分是：在 agent 之间**禁用直接消息**、只允许通过账本读写间接通信。若该条件下收益仍不存在，则本项目制品形态应被判定无效。

**行动项**：把「外部协调者 vs 会话内 coordinator」写成**预注册的可区分假设**，并设计无消息通道的实验条件。

### 5.2 「规格恢复就够了，冲突报告无增量收益」（The Specification Gap）

**必须承认**：在规格信息完整且可恢复的条件下，恢复规格即可回到单 agent 上限，冲突报告无额外收益。

**应答**：该实验的前提是**规格就在输入里**。本项目主场景的前提是**任务声明已存在于会话历史，但无法落入仓库**。因此本项目恢复的是**绑定（binding）**而不是**规格内容**。

**行动项（关键，不得省略）**：把该区别写成**实验前提条件**——先在「规格完整 / 绑定丢失」条件下证明集成结果显著劣于「规格完整 / 绑定存在」，**再**评估恢复绑定与风险报告的增量。若第一步不成立，检测类贡献必须放弃。

### 5.3 「静态预写准入退化为串行」（Claim Plane 确认性研究）

**必须承认**：既有写入前准入的可靠性收益几乎完全来自阻塞（96.7% 序列化）。

**应答**：本项目**不主张**「写入前准入能提高可靠性」；主张的是**在控制有效并行度后收益是否存在**，并把该文自陈的未达目标（「类似串行的质量 + 并行吞吐」）作为本项目的待解问题。

**行动项**：主结果以 \(\tau_{parallel}=E[Y(1)-Y(0)\mid P(1)\ge P(0)-\epsilon]\) 的形式报告；把 lock starvation 与阻塞时长列为显式副作用指标（Before the Pull Request 已将其列为可恢复失效模式）。

### 5.4 「用 AI 治理 AI 是循环论证」（R4，需更换答辩角度）

**原答辩已失效**：外置持久账本已是既有做法（Before the Pull Request 的 git 原生签名日志）。

**新答辩方向**：治理 agent 的论证不应落在「账本外置」这一机制细节，而应落在**可检验的性能主张**：在固定 \(\lambda\) 下，其**单位有效功能的调和成本**是否低于基线，且 \(P\) 未退化。即把 R4 从概念争论转为**实验问题**。这也与 3.2 的第三项贡献一致。

## 6. 主张分级表（替换主文档 §38 的表述方式）

| 阶段 | 可以提出的主张 | 不可提出的主张 |
|---|---|---|
| 合成校准 | 标签与数据格式可被机器检查 | 任何检测性能主张 |
| Gate A | 关键失效维度具有可操作定义；（若成立）绑定丢失独立恶化集成结果 | 「治理有效」「检测准确」 |
| Gate B | 在规格完整但绑定丢失的条件下，恢复绑定有可测量收益 | 「优于 ConflictLens / Rover / STORM」 |
| Gate C | **在控制有效并行度 \(P\) 后**，治理降低单位有效功能调和成本 | 「提高多 agent 开发效率」 |
| Gate D | 该效应跨项目、任务类型与随机种子稳定 | 任何未控制 \(P\) 的收益表述 |

**硬约束（新增）**：Gate B 及以上的任何结果，若不与 \(P\) 同时报告，视为无效结论。

## 8. 残留风险与尚不可声称事项

**尚不可声称**：

1. 任何「优于现有检测器」的性能主张（ConflictLens P 0.91 / Rover / STORM 均未比较）；
2. 任何未与有效并行度 \(P\) 同时报告的治理收益；
3. `LF` 的存在性、可判定性或与 TC/BC/AC 的独立性——**当前零正例**（7 个候选全部不可判定）；
4. 「多开发者 × 多 agent 交互」是主要场景——生态数据（跨 agent 仅 0.5%）不支持；
5. 「外部协调者有效」——在无消息通道条件下**尚未验证**。

**最大风险（未变）**：数据。而且本轮检索使其更明确——真实仓库历史里系统性看不到该失效（STALE-bench 417 对 Django PR 校正后仅 1 例；本仓 Flask 80 个 merge row 全部自动树一致），因此**必须**依赖 agent 侧插桩，而不是更多仓库。

**新增的可用资源**：AgenticFlict（142,652 个 agent PR / 59,412 仓库 / 27.67% 文本冲突率 / 336,380 个冲突区域，作者明确声明不做语义冲突与归属分析）可作为 Gate A 的候选池，其元数据已含文件路径、行区间与双方 SHA-256，有望一次性解决本仓 `adjudication_log.md` 中 D2（缺正例）与 D3（缺同一符号多次触碰证据）两个阻塞。
