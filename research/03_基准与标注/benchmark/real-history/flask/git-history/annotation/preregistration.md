## 1. 本试点要回答的问题

> 在**真实公开仓库的并行变更流**上，Gate A 的九类 ACCD 标签中，哪些可以被两名独立标注者稳定、有证据地判定？

本试点**不**回答：ACCD 在真实项目中的发生率、ISCC 的检测准确率、在线治理是否降低成本。

## 2. 主语澄清（重要的构念边界）

本研究的锚定场景是**单开发者并行开启多个 agent 会话、把不同任务分别交代给它们**（见主文档 §1.1）。本试点使用**人类并行 PR / 分支生命周期**作为「并行变更流」的可得代理，因为可公开重放的多会话 agent 轨迹在本阶段不可获得。

因此：

- 全部结论的外部效度必须限定为「并行变更流的协调可判定性」，不能写成「多会话 agent 开发的协调可判定性」，更不能写成「多 agent 自治协作的可判定性」；
- 代理在两点上可比：任务都由人显式声明、协调者都是人；在两点上不可比：本试点是**不同人**的 PR 而非**同一人**的多个会话，且没有任何 agent 轨迹；
- 每个标注包中的 `agent_context_summary` 是**不可得**的，必须显式标为 `unavailable`，不得用 PR 讨论冒充 agent 上下文；
- 论文中必须报告上述代理关系及其全部威胁（见 `annotation_manual.md` §7）。

## 3. 标签分层

| 层级 | 标签 | 说明 |
|---|---|---|
| 核心 | `BC`、`RT`、`RI` | 进入 Gate B 前必须有可接受的双人一致性 |
| 客观 | `TC` | 由合并机制决定，几乎不含主观判断，作为标注流程的健全性检查 |
| 探索 | `AC`、`CC`、`UA`、`ID`、`LF` | 构念边界尚不确定；允许在结果不达标时降级 |

`ID` 还额外区分 `yes` 与 `possible_ID`：没有成本证据时只能记录 `possible_ID`（规范 §4.8）。

`LF`（可理解性侵蚀，规范 §4.9）是 v1.1 新增的探索性标签，用于覆盖**行为兼容、无任何冲突**但语义归属被稀释的那类失败。它必须独立于 `TC`/`BC`/`AC` 判定，且**不得**仅凭路径/符号重叠判定（H9）。

## 4. 硬约束（非阈值，违反即为无效标注）

| 编号 | 约束 |
|---|---|
| H1 | `confidence = high` 必须伴随非空 `evidence`；无法给出证据的判断不得标为 high |
| H2 | `value = yes` 必须伴随非空 `evidence` |
| H3 | `ID = yes` 必须记录至少一项数值化成本证据；否则必须记为 `possible_ID` |
| H4 | `BC = yes` 的证据必须属于规范 §4.2 的允许类型（回归测试失败 / 验收测试失败 / 契约破坏 / 后续修复或回滚） |
| H5 | 结果视图不得在预测前视图标注锁定之前展示；`phase_2` 记录在 `phase_1_locked = true` 之前无效 |
| H6 | 两名标注者在一致性计算完成之前不得讨论样本 |
| H7 | 标注包中不得包含任何 ACCD 真值字段；标注者也不得读取 `adjudication.md`、`strict_candidate_adjudication.md` 或筛选器初审意见 |
| H8 | 模糊例不得静默删除；`uncertain` 是合法取值而非缺失值 |
| H9 | `LF = yes` 的证据中至少有一条**不得**是 `prediction_view.shared_entities.*`；仅凭路径/符号重叠判定 `LF` 属于无效标注。`LF` 与 `TC`/`BC`/`AC` 用不同证据，不得由后者的 `no` 反推 |

## 5. 就绪门槛（readiness gates）

下列数值用于判定「本试点是否足以进入 Gate B」，其性质是**试点就绪门槛**，不是普适标准。

| 编号 | 对象 | 门槛 | 依据与限定 |
|---|---|---|---|
| G1 | `BC`/`RT`/`RI` | Krippendorff's α ≥ 0.667，目标 ≥ 0.80；原始一致率 ≥ 0.80 | α ≥ 0.667 是 Krippendorff 提出的「暂定可接受」水平，此处仅用于内部门槛判定，不作为论文中的普适阈值 |
| G2 | `TC` | 原始一致率 ≥ 0.90 且 α ≥ 0.80 | TC 由合并机制决定，判定近乎客观，因此门槛高于语义标签 |
| G3 | `AC`/`CC`/`UA`/`LF` | α ≥ 0.60 保留为确认性标签；否则降级为探索性标签 | 允许降级是规范 §7「收缩定义或降级」的直接执行。`LF` 降级前必须先排除 §7 威胁 5 所述的样本结构限制（观察窗口不足导致只能记 `uncertain`） |
| G4 | 高置信度子集 | 双方均 `high` 的标签一致率 ≥ 0.90 | 高置信度判断是论文中最常被引用的证据，必须先自证可靠 |
| G5 | 模糊例 | 逐标签报告比例；任一标签 `uncertain` 比例 > 30% 时必须收缩定义 | 防止用宽定义制造低争议标签 |
| G6 | 分歧处理 | 100% 分歧样本进入第三方裁决，且裁决必须说明分歧来源 | 规范 §6 明确禁止简单多数表决 |
| G7 | 证据完备 | `high` 置信度样本的证据完备率 = 100% | 与 H1 一致，此处作为可报告指标 |

## 6. 统计方法预注册

- **二元化主分析**：`yes` 记为阳性，`no` / `uncertain` / 缺失记为阴性；报告 Cohen's κ、原始一致率、阳性/阴性样本量。
- **三分主分析**：`yes` / `no` / `uncertain` 三分类；报告 Krippendorff's α（名义）与 Gwet's AC1（名义）。
- **为何同时报告 AC1**：本试点正例稀少（见 `strict_candidate_adjudication.md`，7 个候选初审均为负控），κ 在极端边际分布下会被 kappa 悖论压低，AC1 提供对流行率不敏感的对照值。两个指标均报告，不选择性呈现。
- **置信区间**：对 κ 与 α 使用标注者对层面的 bootstrap（10000 次，种子 20260914）给出百分位区间。
  *实现偏离*：本试点只有 2 名标注者，标注者层面的重采样退化为单一抽样单元，故 `inter_rater.py` 实际按**场景**重采样；该替换登记在 `adjudication_log.md` 的 D1。
- **双阶段比较**：同时报告 `phase_1`（仅预测前视图）与 `phase_2`（加入结果视图）的一致性。若结果视图显著提高一致性，说明部分标签依赖事后信息，必须在论文中报告该依赖性，不能只报告 phase_2 分数。
- **`LF` 的共现检查（v1.1 新增）**：必须报告 `LF` 与 `TC`/`BC`/`AC` 的共现矩阵。若 `LF = yes` 几乎只出现在冲突样本中，说明 `LF` 缺乏独立构念，应并入冲突类维度或撤销，不得保留为独立贡献。
- **不做推断统计的声明**：本试点 scenario 数为 7，任何 p 值或效应量都不具备推断意义。报告区间仅用于显示不确定性宽度。

## 7. 停止与降级规则

1. 若某核心标签（`BC`/`RT`/`RI`）一致性低于 G1 且高置信度子集一致率 < 0.90，则本试点不得进入 Gate B，先修订手册并重标；
2. 若某标签的 `uncertain` 比例 > 30%，必须先收缩定义，再考虑重标；
3. 若 7 个候选全部被判为全负例且无任何分歧，则该结果只能作为**筛选负控可行性证据**，不得表述为「ACCD 不存在」；
4. 不得为了让指标达标而删除样本、合并标签或修改手册；
5. **`LF` 的例外处理（v1.1）**：`LF` 的 `uncertain` 高企时，先判断其来源。若来自「样本只提供一对 PR、观察窗口不足以建立反复触碰」（`annotation_manual.md` §7 威胁 5），正确动作是**补充能提供多次触碰证据的候选**，而不是撤销标签；若两名标注者对**证据充分的**样本仍有系统性分歧，则按 G3 降级或按主文档 H6 的否决条款撤销。

## 8. 与既有负控审阅的关系

`strict_candidate_adjudication.md` 已给出 7 个候选的**单研究者初审**，结论为「在当前可得证据下均为负控」。该审阅：

- 可以用于说明筛选器的分层收缩行为；
- **不得**作为标注真值，也不得在标注完成前被标注者阅读（H7）；
- 其判断与最终标注的一致程度本身就是一项必须报告的发现：若双人标注与初审 100% 一致，说明该任务可能过于容易，需引入更难的候选。
