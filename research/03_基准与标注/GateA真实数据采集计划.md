# Gate A 真实数据采集计划

## 1. 目的

将合成校准集替换为可以支持生态有效性分析的真实或受控轨迹。该计划只描述数据获取和验证，不把尚未采集的数据写成结果。

## 2. 当前工作区审计

截至 2026-09-13，工作区中发现的唯一 Git 仓库是：

```text
work/anime-popularity-race
```

该仓库当前存在未提交修改和未跟踪文件，提交历史只有一个初始提交，且没有可用远程地址。因此它不能直接支持历史并行任务回放，也不应被当作真实多 agent 协作数据集。它最多可用于受控生成轨道的测试项目，但需要先复制到独立实验目录，避免接触用户工作区中的未提交内容。

## 3. 两类数据源

### 3.1 真实项目历史回放

候选数据源为公开、具有完整 PR/commit/测试记录的软件仓库。纳入条件：

- 至少有两个时间上重叠或相互依赖的任务候选；
- 能获得基线 commit、两个变更集和合并后的结果；
- 任务描述、代码差异和测试证据均可公开重放；
- 许可允许研究和再分发，或只发布哈希、统计和最小补丁。

不应把任意相邻 commit 当作并行 agent 任务。只有当 issue/PR 时间、作者关系、分支拓扑和变更依赖共同支持“潜在并发”，才进入候选集；最终仍需人工审查。

### 3.2 受控 agent 轨迹

在固定项目版本上运行多个 agent，显式控制任务相似度、实体重叠、依赖结构和启动延迟。每次运行保存：

- 完整任务提示和验收条件；
- agent 模型、版本、提示、工具权限和随机种子；
- 每次文件读写、命令和时间戳；
- 原始 patch、测试输出、合并顺序和返工轨迹；
- 运行失败、超时和中止原因。

受控轨迹可以支持内部因果比较，但不能单独证明真实团队中的发生率。

## 4. 采样分层

至少按以下维度分层采样，避免数据只来自一种项目：

| 维度 | 建议层级 |
|---|---|
| 项目规模 | 小型、中型、大型 |
| 测试成熟度 | 低、中、高 |
| 语言/生态 | 至少三种主流语言或运行时 |
| 任务类型 | 新功能、缺陷修复、重构、配置/文档、测试 |
| 变更关系 | 独立、文件重叠、实体重叠、接口依赖、概念重复 |
| 结果 | 成功集成、文本冲突、语义回归、后续返工、**废弃/未合并分支**、**同一实体被多次触碰但无冲突** |

若某一层样本不足，应在论文中明确报告，而不是用未加权的总体比例掩盖采样偏差。

## 5. 真实标签生成顺序

1. 先冻结基线和任务/变更上下文；
2. 两名标注者只看预测前视图，判断潜在 RT、CC、UA、**LF** 和风险证据；
3. 重放合并并运行测试；
4. 向标注者开放结果视图，判断 BC、AC、RI 和 ID；
5. 对分歧样本进行第三方裁决；
6. 冻结 `labels_v1.jsonl` 后，才能运行检测器或调节阈值。

任何利用后续修复提交生成的标签都必须标记为“结果真值”，不能回填为标注者事前可见信息。

## 6. 数据质量与伦理约束

- 不采集私有仓库、个人对话或未获授权的 agent 轨迹；
- 公开轨迹中的 token、密钥、邮箱和个人标识必须脱敏；
- 模型调用日志可能包含用户代码和提示，应按项目许可和组织政策处理；
- 对开放仓库只发布必要的补丁和元数据，不重新分发受限制的完整代码；
- 记录每个样本的许可、来源 URL/commit、脱敏方式和可撤回方式。

## 7. 采集完成判据

只有同时满足以下条件，才可声称 Gate A 已进入真实数据阶段：

1. 至少一个数据源提供可公开重放的完整 scenario；
2. 所有样本具有冻结的基线、任务、变更、结果和证据链；
3. 关键标签完成双人独立标注和一致性统计；
4. 训练/开发/测试按项目或版本隔离，并完成近重复泄漏检查；
5. 失败运行和模糊案例没有被静默删除；
6. **（2026-09-14 新增）每个候选的 `prediction_view.repeated_touch_evidence.lf_judgeable_from_this_packet`
   必须至少对一部分候选为 `true`**，即候选池中必须存在"同一符号被 3 个及以上不同变更触碰"的样本。
   若全部为 `false`，则该候选池只能校准冲突/重复类标签，**不能**用于校准 `LF`，也不能为 H6 提供证据。
   当前 7 个候选全部为 `false`，因此 Gate A 尚未满足本条。

## 8. 当前决策

当前不应从 `work/anime-popularity-race` 直接生成论文样本，因为它是用户正在编辑的脏工作区，且缺少并行任务历史。下一步应在外部公开仓库上建立独立的历史回放目录，或在复制后的干净项目上启动受控 agent 轨迹；两者都必须与用户工作区隔离。

2026-09-14 的 Flask 初筛已经提供一个排除案例：两个 PR 共享一个测试文件，但没有时间重叠、生产代码实体重叠或可见语义依赖。因此该对被保留为筛选误报负控，不进入真实冲突真值集。该结果强化了“文件路径交集只能筛选，不能标注”的约束。

进一步的本地 Git 提交图筛选在最近 120 个 merge commit 中识别出 80 个 PR-like merge rows 和 805 个“路径或时间”初筛对；其中只有 7 对存在分支生命周期时间重叠，2 对同时共享 `src/`、`lib/` 或 `app/` 路径。该数量级差异说明候选生成必须分层报告，不能把 805 个筛选对当作真实并行冲突样本。

本地提交图还支持对每个 PR-like merge 重放三方合并，比较自动合并树与实际合并树。该重放结果可以筛选“文本冲突或开发者手工改变合并结果”的候选，但不能直接标注语义冲突；必须继续结合任务验收条件、测试和后续修复证据。
当前 80 个 PR-like merge row 的重放结果均为 `auto_clean_same_tree`：自动合并树与实际提交树相同，没有文本冲突或人工树差异候选。这个结果不能被解释为“没有语义冲突”，只说明该 Flask 时间窗口不适合通过 merge-tree 差异直接构造正例。下一步正例获取应使用失败测试、后续修复/回滚、PR 讨论或已有人工验证数据集，而不是继续扩大同一弱筛选信号。
