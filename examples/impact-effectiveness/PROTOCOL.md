# 提前通知能否减少返工：受控回放协议 v1

本协议及 `plan.json` 在首次运行前写入。运行器保存协议、计划、夹具、运行器、分析器以及被测生产代码的 SHA-256；修改实验后必须重新运行，不能把旧结果配给新协议。这是产品行为验收：守住定向交付、去重、适配清除与“不响应就没有改写收益”的边界，不替代真实会话效率测量。

## 要检验的主张

在上游变化、接收方依赖声明准确且提醒被采用的条件下，已有任务状态、版本契约和定向通知能否使尚未完成的工作少返工？同时测量：缺声明、错误声明、忽略提醒、晚提醒，以及频繁测试这一替代方案。

这是确定性工作进程执行真实文件写入、Node 验证与修复的机制实验。它不是自主 coding agent 实验。响应通知的规则是预先编写的，因此最多证明这条因果机制在给定任务和响应策略下成立，不能证明真实 agent 会理解、采纳提醒或节省多少分钟、token。

## 配对条件与实验臂

每个场景分别在消费者完成 0、2、5 项工作后执行同一生产者变化；每次总共完成 6 个渠道的消费者模块。每个「场景 × 变化时点」是一个配对单元，所有臂使用相同初始文件、变化和最终验收，执行次序由固定种子洗牌。重复时点不是独立真实任务样本，不做显著性检验或总体置信区间。

| 臂 | 提醒 | 验证策略 | 隔离的因素 |
| --- | --- | --- | --- |
| git-final | 无 AgentGit | 完成全部工作后验证、失败后修复 | 最终集成基线 |
| record-only | 真实状态/契约/投影，无交付 | 同上 | 只记录本身是否省工、记录成本 |
| targeted | 真实 Hook 在安全点交付，接收方采用 | 最终验证 | 提前获知的机制效果 |
| targeted-half | 同上，预先按配对单元交替采用/忽略 | 最终验证 | 部分采用的敏感性，不是实测采用率 |
| targeted-ignore | 真正收到但忽略 | 最终验证 | 通知到达不等于有效行动 |
| delayed-targeted | 所有工作写完才调用交付 Hook | 最终验证 | 时机消融；底层通知内容相同 |
| git-each | 无 AgentGit | 每完成一项验证，失败即修复；最终再验证 | 与频繁测试的替代方案比较 |

所有臂初始都能阅读 v1 规范。发布后规范更新为同一 v2；最终测试、定期测试失败或收到提醒均可触发读取新规范。工作进程不读取检测器分类决定是否修复，而是比较最新公开规范和已有生成文件；修复不等于无条件改写。最终真值来自 Node 执行结果与独立固定期望值，不能用 `breaking` 声明或检测器输出替代。

## 任务与负对照

三类真实行为变化：返回字段更名、金额从分变元（类型仍为 number）、同步函数变 Promise。多数任务包含六个分散调用点；另设共享适配器场景，后者只需改一个适配器，避免只用放大收益的代码组织方式。独立窗口 C 始终做样式任务，不依赖上游接口。

对照包含：兼容新增、仅修改未使用字段、消费者已经适配、无公开接口变化、遗漏消费者声明、遗漏生产者声明、把兼容变化错误声明为 breaking。后两种缺证据必须报告漏检，错误声明必须报告误报，不能从汇总剔除。正确控制里的兼容更新可能收到 defer 信息，单独计入阅读成本，不能把“无 urgent 误报”写成“没有任何打扰”。

## 指标定义

- 主指标：上游变化后，已经存在的消费者文件被实际改写的次数。由写入前后内容哈希和操作轨迹计算；同一修复在不同文件算多次，不等价于模型轮数、开发时间或难度。
- 过时写入：上游已变后，新生成文件仍与当前公开规范下应生成的内容不同。共享适配器的间接受影响模块不重复计成六次过时接口写入。
- 最终正确性：所有渠道返回固定正确结果；窗口 C 产物存在且正确。统一验收由独立 Node 子进程执行。
- 通知：实际 Hook stdout、字符数、目标会话、紧急/普通分类；把机器可投影但未交付的通知与实际收到的通知分开。断言重复 Hook 不重复交付；适配后投影不再包含可交付提醒。
- 检测真值：把旧客户端与新上游真实执行一次，确定是否确实失效。每个场景只做一次独立真值核验，不把构造标签当运行正确性。
- 成本：分别测量声明/发布/投影/Hook 的机器耗时、验证耗时、通知阅读次数及状态写入次数。进程启动计入 Hook 成本。不人为 sleep 制造耗时；协议验证和留证开销不算产品工作耗时。

净时间收益不能直接用快速模板写文件衡量。本次给出条件公式：

`净收益 = 少做的修复成本 + 少做的验证成本 − 声明维护成本 − 阅读提醒成本 − 协调机器成本`。

其中修复、声明维护与阅读的真实 agent 时间尚未实测。可以给出成本敏感性和盈亏条件，不能据此宣称真实效率提升。

## 实现路径与公平性

真实调用现有 `recordImpactSession`、`recordImpactChange` / 契约注册表、`publishImpactProjection` 和 `plugins/agentgit/scripts/hub.mjs`。没有替换检测器、伪造 Hook 输出或修改生产规则。Hook 输入模拟宿主的安全点。这里调用仍受支持的独立交付处理器 hub.mjs；不是安装后的完整 hook.mjs 分发器，因此机器成本不代表完整插件启动、跟踪和会话生命周期成本。后台投影由 runner 同步触发，因此检测至投递延迟是理想调度；本次不测真实 daemon 轮询、真实窗口宿主集成或并发竞争。模块图使用生产默认配置，但任务只为契约路径提供状态，不能用这批样本评价模块路由的召回收益。

为使因果关系明确，生产者变化按指定交错点串行调度，消费者继续执行；不是实测多进程并行度。所有试验隔离在临时工作区。基线仍使用同样的应用源码和公开规范，所有消费者与生产者改动文件互不冲突。额外用实际 Git 三方合并验证文本干净合并并不保证行为正确。Git 提交/留证不计入产品收益。

## 判定与留证

工程门槛固定在 `plan.json`。任何已测量不达标属于有效结果，运行器退出 1；无法测量或轨迹不一致退出 2。保留逐试验 JSONL、SHA-256、逐臂汇总、每配对单元效果、失败校验输出、实际提醒，以及一个可检查的完整早提醒案例。不要为通过门槛调整场景再继续使用同一批结果。

若机制门槛通过，下一步才是固定模型和预算的真实会话随机配对试验：使用相同仓库快照、任务和上游变化；只随机改变提醒可见性；按任务对分析最终质量、返工工具调用、token、完成时间、声明维护和阅读成本。观察真实采用率，报告所有失败任务，用先导数据估计样本量。不能用本次确定性回放代替这一步。
