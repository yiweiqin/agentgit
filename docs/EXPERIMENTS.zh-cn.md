# 实验与验证

[English](EXPERIMENTS.md) · [文档目录](INDEX.md) · [系统架构](ARCHITECTURE.zh-cn.md)

本文区分回归测试、实际走查和效果测量。命令与行为按 2026-10-10 的代码整理。旧文档中的本机历史样本数量不再作为当前结果展示；需要数字时，应按当前数据重新运行。

## 回归测试与示例

在源码目录运行：

```sh
npm test
npm run test:py
npm run typecheck
node examples/collision/run.mjs
node examples/impact/run.mjs
```

`npm test` 检查编码并运行各包测试；Python 测试验证账本分析器；类型检查覆盖六个包。争用示例在临时账本与 Git 仓库中核验建议，影响示例核验“返回类型变化 → 通知调用方 → 调用方适配 → 旧提醒消失”。示例证明指定行为，不代表实际项目中的检测准确率。

当前测试涵盖结构指纹和扫描限制、文件与函数声明交叉识别、授权、预留、匹配回执、迟到回复、超时、Windows 状态文件替换、选择性影响交付及 Git 操作边界。测试数量以实际运行输出为准，不在文档中固定。

## 真实 Codex 窗口走查

2026-10-10 的走查使用一个已配置协调窗口和两个真实参与聊天。两个场景共保存四份匹配编号的真实回复：

| 场景 | 必须核验的证据 |
| --- | --- |
| 两个聊天声明修改同一份文件 | 各自收到独立检查，并保存匹配的最终回复 |
| 不同文件中写出函数名和变量名不同、归一化结构相同的 JS/TS 实现 | 检查附带代码结构证据，两位参与者分别核验和回复 |

这验证了特定样本的消息与回复链路，不代表检测准确率，也不证明风险已修复。首次启用选择框仍需在已信任钩子的宿主中实际走查；仅打开文件不是有效触发测试。提议输出的单元测试不能证明弹窗显示过。

复现时使用隔离测试工作区，明确授权协调窗口，登记两个参与者的任务和路径，再构造上述两种情况。检查 `checks status` 以及带正确编号的实际最终回复。不要把预检建议、队列接收成功或旧回复算作自动通知与新回执。走查完成后恢复测试文件。操作协议见 [使用说明](USAGE.zh-cn.md) 与 [coordinate.md](../plugins/agentgit/skills/agentgit/references/coordinate.md)。

## 效果测量

| 要回答的问题 | 现有入口 | 必须同时报告的对照或限制 |
| --- | --- | --- |
| 能否从会话历史恢复协作证据 | `examples/real/cases.mjs`、`examples/real/measure.mjs` | 区分同时开发和先后迭代，报告 `entityVisibleCeiling`，每个案例可追溯 |
| 脚本 agent 听取建议后是否减少重复劳动 | `examples/ab/run.mjs` | 同时报独立工作被延后或停止的数量；服从度是设定参数，不是真实 agent 的测量值 |
| 提醒是否过多 | `examples/real/measure.mjs` | 报告工作量、会话时长与误报；建议不能变成强制拒绝 |
| 与 Git 合并检查有什么互补 | `examples/real/run.mjs` | 比较同一案例和时点，披露重建路线，区分文本可合并与行为正确 |

```sh
node examples/real/cases.mjs
node examples/real/measure.mjs
node examples/real/run.mjs
node examples/ab/run.mjs --compliance 0,0.25,0.5,0.75,1
```

真实历史脚本读取本机 Codex rollout 池。`cases.mjs` 与 `run.mjs` 支持 `--workspaces a,b`；`run.mjs` 还支持可选的 `--refs A,B`。报告必须记录输入范围、合格案例数和输出位置。没有合格真实案例时应说明结果，不能编造案例后标成真实数据。

`anchored` 路线把两份补丁应用到共同基础版本；`reversed` 回退路线从最终文本反向重建。后一路线中不重叠修改本来就容易干净合并，不能把它当作 Git 能力局限的独立证据。报告应保留路线名称与补丁核验结果。

模块路由实验应与关闭路由的基线比较召回、比较次数和错误排除。没有跨模块案例的数据池不能证明跨模块召回提高。现有历史实验也未测量新加入的改名代码结构扫描准确率；它需要独立标注的源码样本集，包括相似但不同的实现和跳过语法。

## 报告原则

- 分开记录实际执行结果、静态推理、固定样例预期和待开展实验。
- 收益与代价一起报告：召回率配可见性上限，减少重复工作配独立工作延后。
- 不把脚本服从度当成真实 agent 的效果量，不从一次干净合并推导整体优于 Git。
- 发布前隐藏私人聊天编号、提示文本和路径，并在本地保留到原始证据的映射。
- 结果附代码版本、命令、数据范围与日期。旧测量是历史快照，不是当前产品保证。
